# GLO-0020: Data and consistency

- Status: active

## Aggregate

**Definition.** A cluster of objects treated as one unit for changes, with a single root through which all modification passes. The aggregate is the consistency boundary: everything inside it is consistent after each transaction.

- **Aliases / Acronyms**: —
- **Context**: Applies to the domain model and to deciding transaction scope.
- **Related**: Bounded context, Command, Event store

## Command

**Definition.** A request to change state, named in the imperative. It is validated, may be rejected, and produces events or an error — never a query result.

- **Aliases / Acronyms**: —
- **Context**: Applies to the application layer.
- **Related**: Read model, Aggregate, Event store

## Event store

**Definition.** The append-only log of domain events that is the system of record. State is derived by replaying it; the log itself is never edited.

- **Aliases / Acronyms**: Event log
- **Context**: Applies wherever event sourcing is in use.
- **Related**: Projection, Read model, Aggregate

## Eventual consistency

**Definition.** A guarantee that a derived store converges on the authoritative state after a delay, without guaranteeing when. A read taken immediately after a write may not reflect it.

- **Aliases / Acronyms**: —
- **Context**: Applies to every derived or replicated store.
- **Related**: Read model, Projection, Saga

## Outbox

**Definition.** A table written inside the same transaction as a state change, holding messages a separate relay later publishes. It makes "change state and announce it" atomic without a distributed transaction.

- **Aliases / Acronyms**: Transactional outbox
- **Context**: Applies wherever a state change must produce a message.
- **Related**: Saga, Eventual consistency
- **Source**: _add `path/to/file.ext:line` where this concept lives in the code._

## Projection

**Definition.** A derived view built by folding events into a shape suited to a specific query. It is disposable and can be rebuilt from the log at any time.

- **Aliases / Acronyms**: Denormaliser
- **Context**: Applies to the query side of an event-sourced or CQRS system.
- **Related**: Event store, Read model, Checkpoint
- **Source**: _add `path/to/file.ext:line` where this concept lives in the code._

## Read model

**Definition.** The data shape a query path reads from, modelled for its consumer rather than for storage. It is eventually consistent with the write model.

- **Aliases / Acronyms**: Query model
- **Context**: Applies wherever read and write paths are separated.
- **Related**: Projection, Command, Eventual consistency
- **Source**: _add `path/to/file.ext:line` where this concept lives in the code._

## Saga

**Definition.** A business process spanning several transactions, where each step has a compensating action instead of a shared rollback. It trades atomicity for availability.

- **Aliases / Acronyms**: Process manager
- **Context**: Applies to workflows crossing an aggregate or service boundary.
- **Related**: Outbox, Eventual consistency, Command
