# ADR-0330: Command-query separation of models

- Status: accepted
- Date: 2026-09-15
- Decision key: `cqrs` = `full`

## Context

Reads and writes have different shapes, different volumes, and different consistency needs. Serving both from one model is simple until one of those diverges enough to hurt.

## Decision

**Full CQRS.** Separate command and query responsibilities into distinct models with distinct stores, kept in sync by events.

## Consequences

- Each side is modelled and scaled for its own access pattern.
- Reads are eventually consistent, and the interface has to expose that honestly.
- Two models to keep coherent, and a synchronisation path to operate.

## Alternatives considered

- **Separate read models, one store** — Most of the modelling benefit with none of the consistency cost; no independent read scaling.
- **No, one model for both** — Simplest by a wide margin; the single model degrades as read and write needs diverge.
